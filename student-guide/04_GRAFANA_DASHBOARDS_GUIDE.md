# Grafana Docker Dashboard Guide (Local Setup - No RDS Needed)

**Real-Time Customer Churn Analytics with Grafana, Local PostgreSQL & S3**

This setup lets you run Grafana dashboards locally in Docker **without using or paying for AWS RDS**. S3 is used as your storage for data artifacts and models, while a local PostgreSQL container handles dashboard queries.

---

## 🚀 Quick Start (Running Locally)

### 1. Ensure the Docker Network Exists
```bash
docker network create churn-pipeline-network
```
*(If already created by `docker-compose.yml`, this will simply notify you it exists).*

### 2. Start Local PostgreSQL & Grafana
```bash
docker compose -f docker-compose.grafana.yml up -d
```
This automatically:
- Starts **`churn-postgres`** (a lightweight local PostgreSQL container).
- Automatically executes `sql/create_analytics_tables.sql` on startup to create all tables and views (`churn_predictions`, `high_risk_customers`, `v_realtime_dashboard`, `v_geography_churn`, etc.).
- Starts **`churn-grafana`** and automatically connects it to `churn-postgres`.
- Pre-provisions the **Customer Churn Prediction & Analytics** dashboard.

### 3. Populate Predictions (from S3 or Local Data)
Run the automated population script:
```bash
python scripts/load_data_to_postgres.py
```
*(Or via python in your virtualenv: `.venv\Scripts\python.exe scripts/load_data_to_postgres.py`)*

What this script does:
1. Automatically checks S3 for latest predictions generated by your batch inference pipeline (`artifacts/inference_artifacts/...`).
2. If S3 predictions are not present yet, it gracefully uses the local dataset (`data/raw/ChurnModelling.csv`) to score and populate predictions with realistic timestamps over the last 24 hours.
3. Inserts all metrics into `churn_predictions` and `high_risk_customers`.

### 4. View Your Dashboards
- Open your browser to: **[http://localhost:3000](http://localhost:3000)**
- **Username**: `admin`
- **Password**: `admin`
*(Or view without login, as anonymous viewer access is enabled).*

## 📊 Pre-Provisioned Dashboard Breakdown

The dashboard is auto-loaded from `grafana/dashboards/customer_churn_analytics.json`:

1. **Top KPI Stat Cards**:
   - **Total Predictions**: Real-time counter of total customer predictions.
   - **Predicted Churners**: Number of customers predicted to churn.
   - **Current Churn Rate (%)**: Percentage with color indicators (🟢 <15%, 🟡 15-25%, 🔴 >25%).
   - **High-Risk Customers**: Count of customers where `risk_score >= 0.7`.
   - **Average Risk Score**: Radial gauge displaying aggregate customer risk from `0.0` to `1.0`.

2. **Trends & Distributions**:
   - **Prediction Volume & Churn Over Time**: Hourly breakdown of volume vs. detected churn.
   - **Churn Rate by Country (%)**: Bar chart comparing churn across France, Germany, and Spain.
   - **Customer Demographics by Gender**: Donut chart displaying gender distribution.
   - **Churn Breakdown by Number of Products**: Stacked bar chart showing retention and churn by product count.

3. **Operational Tables**:
   - **🚨 High-Risk Customer Action List**: Prioritized list of high-risk customers with balance, tenure, and detection timestamp for proactive retention.
   - **📡 Live Prediction Ingestion Stream**: Auto-refreshing feed of recent scored events.

## 🔄 Using with Kafka Streaming (Optional)

If you are running the real-time Kafka streaming containers (`docker-compose.kafka.yml`):
- Set `RDS_HOST=churn-postgres` in your `.env` (or pass it in the container environment).
- The `analytics` container (`kafka/analytics_service.py`) will automatically write live streaming predictions directly into the local `churn-postgres` container!

## 🛠️ Management Commands

| Action | Command |
|---|---|
| Start Local DB & Grafana | `docker compose -f docker-compose.grafana.yml up -d` |
| Populate Data | `python scripts/load_data_to_postgres.py` |
| Stop Services | `docker compose -f docker-compose.grafana.yml down` |
| View Grafana Logs | `docker compose -f docker-compose.grafana.yml logs -f` |
| Reset Local Database | `docker compose -f docker-compose.grafana.yml down -v` |
